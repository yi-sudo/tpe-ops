# TPE//OPS 臺北市政營運中樞（原型）

給臺北市政府內部使用的跨局處營運儀表板原型。資料全部來自臺北市和交通部的開放資料，涵蓋「市政 debug松」題目頁（https://puma.taipei/hackathon）的題目 1–6。

- 本專案自行開發、免費開源，**沒有報名黑客松**，也**不是臺北市政府的官方系統**
- 每個題目都看三件事：
  - 問題集中在哪些里
  - 解決後能改善多少（成效模型與情境滑桿）
  - 現在的即時狀況
- 也呈現題目之間的關聯：哪些問題集中在同一批里、哪些局處要一起處理

## 快速開始：只看儀表板（不需要金鑰）

處理好的資料（`dashboard/public/data/`，約 10 MB）已經放在 repo 裡，只要 Node.js 22 以上：

```bash
git clone https://github.com/yi-sudo/tpe-ops.git
cd tpe-ops/dashboard
npm install
npm run dev          # 開啟 http://localhost:5173/
```

- 畫面上的數字是 repo 內資料的擷取時間（每個圖表都有標示），不會自動更新
- 頂列的即時串流會顯示「延遲」，因為本機沒有在跑收集程式。要看即時資料請照下一節操作

打包成靜態網站：`npm run build`，輸出在 `dashboard/dist/`，可以放到任何靜態主機（GitHub Pages、Netlify 等）。

## 完整執行：自己抓資料、更新即時資料

需要 Python 3.11 以上、Node.js 22 以上，以及 TDX 的 API 金鑰（申請方式見下一節）。

```bash
# 1. Python 環境
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 2. TDX 金鑰
cp .env.example .env                                # 填入 TDX_CLIENT_ID、TDX_CLIENT_SECRET
.venv/bin/python tdx_check.py                       # 驗證金鑰，成功會印出 OK 和一段測試資料

# 3. 抓資料（只有這一步會連外部 API，結果存在 data/raw/，不會提交到 git）
.venv/bin/python -m pipeline.fetch                  # 靜態資料（TDX 有節流，每 13 秒一次）
.venv/bin/python -m pipeline.fetch --live           # 一次即時快照
.venv/bin/python -m pipeline.history --days 10      # 選用：TDX 歷史 VD，04 改用真實晨峰曲線（每天約 1.1 GB、100 秒）

# 4. 處理成儀表板資料（只讀本機檔案，約 6 秒，覆寫 dashboard/public/data/）
.venv/bin/python -m pipeline.build

# 5. 另開一個終端機，常駐收集即時資料
.venv/bin/python -u -m pipeline.collect_live

# 6. 儀表板
cd dashboard
npm install
npm run dev                                         # http://localhost:5173/
```

沒有執行第 3 步的 `pipeline.history` 時，04 的晨峰曲線會用模擬資料，畫面上會標示。

## 申請 TDX 金鑰

交通部 TDX 運輸資料流通服務的資料（路段、路況、捷運車站與線型、VD 歷史資料）需要金鑰，免費申請：

1. 到 https://tdx.transportdata.tw/ 註冊會員，完成 email 驗證
2. 登入後進入「會員中心」→「資料服務」→「API 金鑰」，系統會產生一組 **Client Id** 和 **Client Secret**
3. 把兩個值填進專案根目錄的 `.env`（由 `.env.example` 複製）：
   ```
   TDX_CLIENT_ID=你的 Client Id
   TDX_CLIENT_SECRET=你的 Client Secret
   ```
4. 執行 `.venv/bin/python tdx_check.py` 確認可以換到 token

注意：

- `.env` 已在 `.gitignore`，**不要提交、不要貼到 issue 或聊天室**。外洩時到 TDX 會員中心重新產生
- 一般會員每分鐘只能呼叫 5 次。`pipeline/common.py` 已經做好節流（TDX 每 13 秒一次）和 429 重試
- access token 有效 24 小時，快取在 `data/.cache/`，不會每次重新申請
- 端點、參數和歷史資料的細節見 `api.md`

其他來源**不需要金鑰**：

| 來源 | 用途 |
|---|---|
| 臺北市資料大平臺（data.taipei） | 行道樹、清潔箱、陳情、人口、餐飲業、消防等 |
| 臺北市交通局 tcgbusfs | 公車路線、站牌、即時位置、預估到站、VD |
| 公園處、大地處（soil.taipei）、統計資料庫（tsis） | 公園樹木、土壤液化、建物與公車統計 |
| 水利處（wic.gov.taipei） | 雨量站即時資料（使用水利處公開的資料 key，已寫在 `pipeline/sources.py`） |
| 見鼠地圖（ratdar.taipei） | 見鼠通報 |

沒有 TDX 金鑰時，`pipeline.fetch` 仍會抓完其他來源（TDX 的項目會列為失敗），但 `pipeline.build` 需要 TDX 的捷運車站和路段線型，所以**要自己重建儀表板資料就必須申請金鑰**。只看儀表板不需要。

## 資料更新

| 資料 | 指令 | 頻率 |
|---|---|---|
| 靜態資料 | `pipeline.fetch` | 超過 7 天才重抓；抓取失敗時保留舊檔 |
| 即時資料 | `pipeline.collect_live`（常駐） | VD、公車位置每 60 秒；公車到站、路況每 5 分鐘；雨量每 10 分鐘 |
| TDX 歷史 VD | `pipeline.fetch --only vd_hist` | 前一天的資料隔天清晨才發布，建議平日 06:00 後執行；已存的日期不重抓 |
| 儀表板資料 | `pipeline.build` | 靜態資料或歷史 VD 更新後執行，然後重新整理頁面 |

- 即時資料每次抓取都存一份快照，預設保留 3 天
- 儀表板每 15 秒檢查一次即時資料有沒有更新
- 頂列顯示 5 個即時串流的狀態；收集程式超過 10 分鐘沒有更新時會警示

## 真實資料與模擬資料

目前只有 **1 項模擬資料**，其餘都是真實的開放資料。部分數值是由真實資料加上假設推估，所有假設都列在各題的情境面板。

| 題目 | 真實資料 | 模擬資料 | 推估與限制 |
|---|---|---|---|
| 01 樹蔭 | 行道樹、公園樹木、樹穴、人行道範圍、公園、各里年齡人口 | — | 樹冠寬由胸徑推估；沒有逐年移除紀錄 |
| 02 清潔箱 | 清潔箱、公車站牌（停靠路線數）、捷運站與進出量、餐飲業清冊、攤販集中場 | **各清潔箱的每日填滿速度**：沒有開放的滿溢感測資料，依周邊人流需求推估 | 需求權重和服務半徑 150 m 是假設 |
| 03 鼠患 | 見鼠地圖通報、餐飲業清冊、垃圾車點位、雨水人孔、攤販集中場、登革熱病媒蚊密度 | — | 風險權重是假設；見鼠通報只用來驗證，有民眾回報偏誤 |
| 04 車流 | VD 靜態與即時、TDX 路段與即時路況、TDX 歷史 VD（逐分鐘） | — | 車道容量是假設；延滯模型用實測車速校準；資料品質規則在 04 的「晨峰資料品質」面板 |
| 05 公車 | 公車路線、站牌、軌跡、時刻表、即時位置與到站、聯營公車業務統計、捷運站／路線／進出量、TDX 路段即時路況、各里年齡人口 | — | 沒有各站上下車刷卡人次，冷區用每千人通過班次、離捷運距離和長者比例評估；營運成本是假設 |
| 06 耐震 | 土壤液化潛勢、消防通道清冊、消防栓、各里年齡人口、建物棟數統計、獨居長者 | — | 沒有逐棟屋齡與結構開放資料，屋齡只用全市統計；風險權重是假設 |

另外：

- 六題都顯示近 12 個月的 1999 陳情件數和處理天數（臺北市陳情系統類別資料）
- 里界、區界、捷運路線和公車路網是所有地圖共用的底圖
- 雨量站即時資料只用在總覽的即時監看和頂列的串流狀態

模擬資料用在：

- `layers/bins.json` 的 `fill_per_day` 欄位（02 地圖上的清潔箱填滿速度）
- `impact.json` 題目 2 的「依滿溢度清運」趟次和固定班表下的滿溢箱數

完整清單見儀表板的「DL 資料血緣」頁，或 `dashboard/public/data/catalog.json` 的 `mock`。

**不使用的資料：** 「市長，你給我聽好了」市民痛點資料只提供給黑客松參加者，本專案不使用。

## 資料快取

- 抓取和顯示分開：
  - `pipeline/` 把原始回應存在 `data/raw/{來源}/`：時間戳快照、`latest`、`meta.json`（來源網址、擷取時間、筆數、是否模擬）
  - 儀表板只讀 `dashboard/public/data/` 的本機檔案，不直接呼叫外部 API
- TDX 每分鐘只能呼叫 5 次，token 會快取 24 小時
- 規則細節見 `CLAUDE.md` 的「資料快取規則」
